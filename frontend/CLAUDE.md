# Frontend conventions

Loads when working under `frontend/`. Cross-cutting rules are in the root `CLAUDE.md`.

SvelteKit 3 on **Svelte 5 (runes only, no legacy syntax)**, TypeScript 6, Vite 8 (Rolldown), Tailwind v4, `adapter-static` → `build/`. Kit config lives in `vite.config.ts` (`sveltekit({ … })`; there is no `svelte.config.js`). Imports use `#lib/…` (`package.json` "imports" + a matching tsconfig `paths` entry); worker URLs stay relative (`lib/workers/spawn.ts`). Node is pinned in `.node-version` (Kit 3 needs ≥ 22.17). Notable libs: `argon2-browser`, `dexie` (IndexedDB: encrypted cache of server data and, in hybrid mode, the home of grading results), `pdf-lib`/`pdfjs-dist`, `zxing-wasm` (QR decode) / `qrcode`, `texlyre-busytex` (WASM LaTeX). `svelte-check --threshold error` should be clean; treat any error as new. Build/CSP/BusyTeX details: `docs/dev/build_and_csp.md`.

## Components

- New components go in `src/lib/components/<feature>/`. Shared primitives live in `components/ui/` (list: `ui/index.ts`, import from `#lib/components/ui`). Loose files at the `components/` root are legacy; don't copy them.
- **Raw exports** (issue #82) live in `src/lib/export/` (plain ZIP via `ZipBuilder`, dialog `components/export/ExportOptionsModal`). Burned-in graded PDFs come only from `renderGradedPdf` (`export/gradedPdf.ts`) and strokes only from `grading/strokeRenderer.ts`; exam sources from `prepareExamSources`, exercise documents from `buildExerciseDocument`. Reuse them, don't fork.
- Routes hold data loading, handlers and session state; components hold markup. Wire with callback props (`onAction={handler}`, `bind:value` on `$bindable` props); no `createEventDispatcher`, `on:` directives, `<slot>` or `export let`. Form primitives (`TextInput`, `Textarea`, `Select`, `Radio`, `SuggestInput`) take DOM-named handler props (`oninput`, `onchange`, …) and compose them with their own.
- Prop-drilling exception: `src/lib/grading/gradingStore.ts`. Leaf grading components subscribe directly (15+ interdependent fields, justified in-file).
- **Runes rules that protect storage behaviour** (the Svelte 4 → 5 migration relied on them):
  - Side effects are `$effect.pre` blocks that read their trigger names first and run the body in `untrack(…)`; otherwise a load/save re-fires whenever anything it reads changes. Keep existing guards (`loadSeq`, `loadedFor`, …).
  - A `$derived` over a store (`$derived($store.x)`) changes synchronously on `set`: compute a target index once, never re-read the derived after setting it (the grade page's Next loaded the student after next and saved their MC rows onto the wrong one, issue #85).
  - Put `$effect.pre` blocks **at the end of the instance script**: they run synchronously where declared, so one above a `let` it (or a function it calls) touches throws a TDZ error (Svelte 4 ran `$:` after all declarations).
  - Records and collections that reach repositories, Dexie, stores, workers or crypto are `$state.raw` and updated by reassignment (`arr = [...arr, x]`). A deep `$state` Proxy breaks `structuredClone`/IndexedDB/`postMessage` and identity checks. Deep `$state` is for primitives and local edit buffers only; pass those on as `$state.snapshot(x)`.
  - `onwheel`/`ontouch*` are passive in Svelte 5. A handler that calls `preventDefault()` needs a non-passive listener (see `ZoomableImage`, `ScanCanvasViewer`).

## Design system (Artemis look, tokens re-implemented, no code copied)

- **Inline Tailwind utilities in markup** are the house dialect. A component `<style>` block is only for what utilities cannot express (a class shared by many siblings, a keyframe). Never add a `.css` file; the only ones are `src/app.css` and `routes/+layout.css`.
- **Light + dark** via `<html data-theme>`, resolved by `lib/stores/theme.ts` (pref `bg_theme`: `system`/`light`/`dark`). An inline no-flash script in `app.html` applies it before first paint; its storage key must stay in sync with the store.
- **Tokens** live in `@theme static` blocks in `src/app.css` (light plus a dark override set). Use the token utility (`bg-surface-raised`), never a raw hex or Tailwind shade. Families: surfaces, lines, text (`content`/`muted`/`subtle`), `accent` (text/links) vs `primary` (fills) + `primary-contrast`, state families `danger|success|warning|info` each with `-contrast` (text on the fill) and `-fg` (text on a surface), `navbar*`, widths `max-w-form|narrow|medium|wide|page`, z-index ladder vars (`--z-dropdown` 1000 / `--z-modal` 2000 / `--z-toast` 3000), grade colours.
- **Rules**: never use a fill colour (`primary`, `danger`, …) as text colour; use `accent` / `*-fg`. Radius `md` for controls and panels, `xl` for cards and dialogs. No emoji/glyph chrome: icons are FontAwesome through `ui/Icon` with per-icon imports from `@fortawesome/free-solid-svg-icons`. Variant maps (`{ primary: "bg-primary …" }`) must hold literal class strings so Tailwind sees them. `PageShell` is the one page root.
- **Overview lists** (exam page `routes/+page.svelte`, exercise library `routes/exercises/+page.svelte`) share one set of parts; extend them, don't fork: `ui/FilterLayout` (+ `common/ListFilterPanel`, `utils/listFilter.ts`), `ui/ExpandableCard`, `utils/lazyMap` + `utils/expandSet` (errors are `error`, never "empty"), `common/DeleteWithUsageModal` over `ConfirmDeleteModal` (`busy` + inline `error`, no `alert()`), `stores/previewFlow` + `common/PreviewHost` (Preview = last compile from the in-memory `compileCache`, else compile in the modal; owns the object URLs; exam previews reuse a compile only if it matches the current sources, `getCurrentExamPreview`, else recompile, issue #135), `exercise-library/groupExercises`. Lists stay visible while refreshing (`isLoading` = first load only; overlapping refreshes coalesce). Exam compile (preamble, `buildExerciseInputs`, resources) lives in `lib/exam/examPreview.ts`, shared by the exam page, OMR prep and the dashboard preview. Every compiled-PDF preview offers "Report LaTeX layout problem" (issue #134) in `DualPdfPreview`'s `footer` bar (`components/layout-report/LayoutReportButton`, files from `lib/layout-report/collect.ts`; `createPreviewFlow({ reportFiles })` for modal previews); a new preview site adds it too.
- **Modal** (every dialog goes through it): sizes `small|medium|large|full` + `tall` (`full` fills the viewport minus a 1rem frame); backdrop click is off by default (`closeOnBackdrop`) so a stray click cannot discard input; below `sm` everything but `small` is a full-height sheet. The panel is a size container, so inside it use `@md:`/`@xl:` container variants. Scroll lock goes through `lib/utils/scrollLock.ts` and locks `.app-main`. Only the topmost modal handles Escape/Tab. Inline errors go through its `error` prop (`errorActions` for a retry); a loading modal shows its spinner only while it has neither data nor an error.
- **Tables**: `.data-table` (+ `-compact|-striped|-hover`) in `app.css`, wrapped in `TableScroller`.

## Responsive and app shell

- **Mobile-first, always.** Unprefixed classes describe the phone; `sm:`/`md:`/`lg:`/`xl:` add back. Tailwind's default breakpoints only (640/768/1024/1280). **Never** `max-[900px]:`, `max-md:`, or a raw `@media` in component code. Every grid/flex child that can hold wide content needs `min-w-0`.
- `lib/stores/viewport.ts` (`isPhone`/`isTablet`/`isDesktop`/`isTouch`) is only for places where a narrow screen changes *behaviour*. Anything purely visual belongs in a breakpoint variant.
- **Target devices**: unscaled 1920×1080 (primary); 1920×1080 laptops at 125/150 % scaling (1536×730, 1280×600, tight height); iPad Pro 12.9″ portrait 1024 (= `lg`) and landscape, touch/pencil; 6–7″ phones portrait. Touch targets ≥44px via `pointer-coarse:`.
- **Shell** (`routes/+layout.css`): `.app-layout` is `100dvh` with `overflow: clip`, body is `overflow: hidden`, and `.app-main` is the only scroller. `AppFooter` is the last child of `.app-main` on every route; the grade root fills via `flex-1 min-h-0`. Don't reintroduce `overflow: hidden` on the layout, don't nest a second `100vh`/`100dvh`, and never put `min-h-full`/`h-full` on a page root (page plus footer would overflow by the footer's height); centred pages use `PageShell center`.
- `LatexEditor` has CodeMirror search (Ctrl+F, Ctrl+H for replace; phrases from `editor.search.*`). Escape that closes the search panel is stopped at the editor so the surrounding `Modal` stays open.
- **Exercise editor on small screens**: the metadata lives in the dialog header (`exercise/ExerciseMetaFields`: beside the title from `@6xl`, below it from `@3xl`, folded into a one-line summary below). Below `@3xl` the dialog body is one natural scroller (no fixed-height columns) and the LaTeX palette is folded (`bg_latex_palette_open`; unfolded by default only from 1280×900). Keep the code editor in the first screen on a 360×780 phone and a 1280×600 laptop: anything new above it must fold too. `LatexEditor`'s wrapper must not get `overflow-hidden`/`min-h-0` back: its minimum then ignores the palette and flex parents clip the last lines (issue #154).
- **LaTeX palette**: general chips in `lib/latex/quickInsertMacros.ts` (labels `editor.macros.*`), subject tabs in `lib/latex/subjectSnippets.ts` (labels in the `snippets` namespace, MINT topics from LehrplanPLUS Gymnasium). Every package a snippet uses is preloaded by `packages.sty` (chemfig, circuitikz, mhchem since issue #154); a snippet never adds `\usepackage` lines. Check new snippets against both engines: the browser bundle (TeX Live 2026) lacks some packages (mhchem, chemgreek, simplekv, bbding, pifont, struktex are vendored in `backend/latex-assets/sty/` for it; the worker flattens `sty/*.sty` and `sty/*.tex`), Tectonic's bundle is TeX Live 2022 (chemfig 1.5+: `\charge`, no `\lewis`).
- `PreviewBanner` (mounted in the root layout, outside `.app-layout`) is a fixed top-left corner ribbon shown only when `isPreviewBuild` (`__IS_PREVIEW__`); `pointer-events-none`, `--z-dropdown`, so it never blocks the navbar. Re-check it against the burger at 320px when the header changes.
- `AppNavbar` shows links from `xl`, burger + `NavDrawer` below; minimal variant on locked/public pages; none on the grade page. Below `sm` the navbar has no room for the version, data and LaTeX pills or the Workspace menu (320px, issue #67): data/LaTeX are rows in the drawer, the workspace actions sit in the account menu, the version stays in the footer. The shell clips overflow silently, so re-measure the header at 320px after adding a control. Exam steps live in `ExamSidebar` from `lg` (pref `bg_sidebar_collapsed`), in the drawer below; `routes/exam/[id]/+layout.svelte` publishes `examNavContext` (`lib/stores/shell.ts`) for both.
- **Cross-links** (issue #151): a name whose target is a dialog opens it in place via `ui/LinkButton`: exercise names open `ExerciseEditorModal` everywhere (the caller refreshes its own data in `onSave`), library "used in" chips open `exam/ExamSummaryModal` (with "Open in new tab"). A name whose target is a page (student → grading, analytics group → library) is a `ui/CrossLink` (new tab + ↗). Hrefs come from `lib/utils/links.ts`. Page-flow navigation (sidebar, back, next/prev, step buttons) stays same-tab and uses `Button href`, not `goto`, so middle-click works.
- E2E: `npm run test:e2e` (Playwright, projects `desktop` 1920×950, `ipad-portrait`, `phone`; shell navigation in `e2e/helpers/nav.ts`). The browser's API calls are answered by the stateful in-memory fake `tests/helpers/fakeApi.ts` (shared with the vitest archive tests, wired in by `e2e/helpers/backend.ts`), so no backend has to run; sign-in helpers live in `e2e/helpers/flows.ts`. A request the fake has no route for fails the test: extend the fake rather than the app. Not part of CI.

## i18n (German / English)

UI text lives in typed catalogs under `src/lib/i18n/`; language toggle in `AppNavbar.svelte`, radio section in `SettingsForm.svelte`.

- `de/<ns>.ts` is the **source of truth** (`export const <ns> = {...} as const`). `en/<ns>.ts` is annotated `Translations['<ns>']`, so a missing or misspelled key is a `svelte-check` error. `types.ts` widens the literals back to `string` (German pins key *structure*, not wording). A new namespace must be added to both `de/index.ts` and `en/index.ts`.
- Markup: `{$t("ns.key")}`, `{$t("ns.key", { name })}`. Plain `.ts`, `alert`/`confirm`/`prompt`: `translate("ns.key")`. Runtime-composed keys: `tOptional` / `translateOptional`. Dates and numbers: `$fmt.date` / `$fmt.number` / `$fmt.percent` from `lib/utils/format.ts`.
- Locale is `bg_locale` in `safeLocalStorage`, detected as saved → `navigator.language` → `en`. Missing key falls back to German, then to the key. Interpolation only, no ICU plurals.
- Backend errors are localized **client-side** by the `code` the API sends next to its English `detail` (`errors.code.<CODE>`, applied in `lib/api/client.ts`); `err.message` stays the fallback.
- **Exam/PDF output is deliberately NOT translated**: `Schulaufgabe.sty` captions, `\begin{Aufgabe}`, `\Loesung*`, the MC rubric prose and German seed defaults (`testart`/`fach`/`title`) are exam content and a stable macro API. `routes/exam/new` keeps `toLocaleDateString("de-DE")` because that value is printed in the PDF.
- Legal pages: German is legally binding (§ 18 MStV, § 5 DDG, Art. 12 DSGVO). `en/legal.ts` holds the German text as a placeholder; **never** machine-translate it. The operator's identity comes only from the `VITE_LEGAL_*` build variables (`lib/legal/operator.ts`, `docs/deployment.md`), never from committed text; retention numbers come from `GET /privacy/retention`.
- `tests/locale.test.ts` guards detection, persistence, interpolation and de/en key parity.

## Multiple Choice (MC) data model

- **MC question**: an individual `Exercise` / `ExerciseRecord` (`question_type: mc|sc|tf`, `correct_answers` JSON / `options` & `correctAnswers` arrays, `penalty`). Variants use the standard `exercise_group_id` + `variant_key`.
- **MC group (`\McExercise{a}{b}{c}`)**: a per-exam layout container (`ExamMcGroup` / `ExamMcGroupRecord`, 1+ sub-items, no cap on count or size) linking members via `ExamExercise.mc_group_id` and `sub_index`. Rendered into one `\begin{Aufgabe}` by `format_mc_group_latex()`. An exercise belongs to at most one group (staging rules: `lib/exam/mcGroupStaging.ts`, shared by `exam/new` and `exam/[id]`).
- **Grading and statistics are strictly per question (`exerciseId`)**; `ExamMcGroup` is only LaTeX layout metadata.
- **Group membership lives on the junction row**, not on the exercise: `ExamExercise.mc_group_id`/`sub_index` server-side, `examExercises.mcGroupId`/`subIndex` in Dexie. The Dexie primary key is `[examId+exerciseId]`, so **any `examExercises.put`/`bulkPut` that omits those two fields silently dissolves the group** (it renders empty and its members reappear as standalone exercises). Always merge onto the stored record or carry the fields through from the API response.
- Group ids are **client-chosen and stable**; `_persist_mc_groups` keeps them and answers 409 on collision. `exam_exercises.mc_group_id` is `ON DELETE SET NULL`: dissolving a group must never delete its members' exam links.
- `PATCH /exams/{id}` replaces `mc_groups` and `exercise_links` wholesale. An exercise may appear **once** in `exercise_links` (`(exam_id, exercise_id)` is the primary key). `buildExamLinkPayload()` in `exam/[id]/+page.svelte` is the single builder for both the Dexie records and that payload; don't hand-roll a second one.
- Past 26 members the sub-label switches from `a)` to `1)`: `mcSubLabel` (`lib/grading/mcGroupLabels.ts`) and both group formatters must agree. An MC question's option column count lives only in its LaTeX body as `\LoesungMulti[N]` (`lib/latex/mcOptions.ts`). Options and answer key are read from the LaTeX too (`printedMcOptions`: one per `\multi`/`\Lmulti`, in OMR `optionIndex` order); the stored `correct_answers` is only a fallback, since LaTeX-only edits (new variant, resync) leave it stale.
- In MC mode the editor shows only `exercise/McOptionsEditor`; the composed LaTeX (a duplicate of question + options) opens on demand in its own dialog ("LaTeX code").
- The editor's MC question is **LaTeX, never escaped** (`buildMcOptionsLatex`; escaping it on every rebuild corrupted it). Option texts are plain input and escaped, but an option keeps its parsed `source` until its text is edited, and text after the `\LoesungMulti` block survives a rebuild. Saving reads the options from the LaTeX instead of rebuilding it. While the block is unclosed (`malformed`, e.g. mid-typing) the MC editor never rebuilds. `LatexEditor`'s `onChange` fires only for user edits, never for an outside `value` change.
- `examItems` (the exam page's item order) is view state, rebuilt on load from persisted `order_index` via `buildExamItems()`. Group members share their group's `order_index`.
- **Page breaks** (`exams.page_breaks`, `ExamRecord.pageBreaks`): ids of the exercises / MC groups that start on a new page, plaintext layout metadata. `buildExerciseInputs(..., pageBreaks)` emits `\newpage` (never before the first block), the server's `compile_exam_latex` does the same; archive import remaps the ids (`lib/exam/pageBreaks.ts`). The OMR template's `exercisesHash` (`computeOmrTemplateHash`) covers the answer key plus the blank sheet's whole LaTeX, so exercise edits, reordering, breaks and header changes mark it stale (issue #135); scan and verify rebuild it, the exam page only warns.
- **Name line** (issue #127, `exams.name_line`, `ExamRecord.nameLine`): the `Schulaufgabe.sty` option `namenszeile`, added only by `withExamOptions` (`lib/exam/examPreview.ts`) and `compile_exam_latex`. It keeps the QR box (same size, scanning unchanged) and adds a name line beside it.
- OMR detection internals: `docs/dev/omr.md`. Training-data donation: `docs/dev/training_donation.md`.

## Exercise structure (issues #77-#79)

Part exercises (`\begin{Teilaufgabe}[fixed]{subtitle}`, a/b/c with own score box), fixed scores (`\FestePunkte{N}` or the `[N]` option), requirement level (`\AFB{I|II|III}`) and competencies (`\Kompetenz{…}`) are LaTeX macros in `Schulaufgabe.sty`; there are no DB columns, so they travel with variants, copies, sharing and archives. The editor reads and writes them only through `lib/latex/exerciseStructure.ts` (`parseExerciseScore` delegates to it; its counting must match the `.sty`). Grading stays per exercise. MC bodies are rebuilt from question + options, so the editor strips and re-applies the AFB/competency tags around `buildMcOptionsLatex`. The editor's controls for them are `ExerciseStructurePanel`, shown in `ExerciseStructureModal` from the score button in the LaTeX header row (not inline, to keep the code editor in the first screen).

## LaTeX resource files

Teacher-uploaded files an exercise's LaTeX references (`\includegraphics{figure.png}`, `\input{data.tex}`). Any type except SVG (refused with a convert-to-PDF hint: `src/lib/latex/resources.ts`, mirrored in `backend/app/services/latex_resources.py`; keep the two in sync).

- Attached **per exercise**, referenced by **flat sanitized filename**; files are written next to `main.tex` in both engines, never in a subdirectory. Names that collide with a bundled `latex-assets` file (including the worker's flattened `sty/x.sty` → `x.sty`) are rejected at upload.
- Limits: 5 MB per file, 25 MB per exercise, 20 MB / 30 files per compile request; `BODY_LIMIT_COMPILE` 28 MB, `BODY_LIMIT_RESOURCE` 7 MB.
- Storage: Dexie `exerciseResources`, bytes AES-256-GCM encrypted; server table `exercise_resources`, bytes **plaintext** (same as `exercises.latex_body`; Tectonic cannot read ciphertext).
- The editor stages files under a throwaway id (never the exercise id) and `exerciseResourceRepository.commit()` moves the staged set onto the exercise on save. Cancel discards. The staged set is authoritative on commit: files removed while editing are deleted server-side too. The staging area is seeded asynchronously (`seedStaging`): the panel loads only once `seeded` is true and `commit` awaits the seed, otherwise the list opens empty and an early save would delete the files.
- Local compile: `compiler.ts` → worker `additionalFiles`. Server compile sends `resource_exercise_ids` for saved exercises and inline base64 only for staged/local-only files. `POST /exams/{id}/compile` always reads rows from the DB.
- Two exercises with *different* files under the same name is a hard error before compiling (`mergeResources`); identical bytes are deduped.
- Resource API calls pass `silentError` and report in the panel; a 404 for an exercise the server has never seen must not raise the global toast.
- **Exam logo** (issue #46) is not a resource: the account choice (default MTG logo when unset, `none`, or own file) / per-exam override live on the server (`lib/latex/logo.ts`, `backend/app/services/logo.py`). The compile writes it as `examance-logo.<ext>` (reserved names) and `Schulaufgabe.sty`'s `\ExamLogo` prints whichever exists. Exam compiles pass `logo: await resolveCompileLogo(examId | null, useLocal)`; its fingerprint is part of the compile-cache hash. The logo is part of the exam everywhere it travels: `.bgproj` archives carry `examLogos` (export `exportExamLogo`, import `restoreExamLogo`, conflicts remap it with its exam) and the account export includes the files.
- A missing graphic does not fail XeLaTeX. The worker reports `missingGraphics` and callers surface it; a successful compile is not proof the figures rendered.
- **LaTeX packages** (issue #108, rules in `docs/dev/latex_packages.md`): account list (`/user/latex-packages`, settings card), exam additions (`ExamRecord.latexPackages`, exam data dialog) and exercise `\usepackage` lines (editor panel, kept in the LaTeX so they travel) are merged by `lib/latex/packages.ts`, mirrored in `backend/app/services/latex_packages.py`; keep both in sync. Every document builder writes the result before `\documentclass` with `withPackages` (options only via `\PassOptionsToPackage`, packages in `\ExamancePackages`, which `packages.sty` runs before hyperref); never add `\usepackage` lines to a builder for user packages. Common TikZ libraries are preloaded in `packages.sty` (issue #107).
- The task score box sits at the right end of the title line (bottom on the baseline, `\hangindent` shortens that line), like the `Teilaufgabe` box. Never a `wrapfigure` (it left `\linewidth` 3cm short for the whole first paragraph, so grids came out narrow, and wrapped differently per document; issues #140, #138) and no band above the title (wasted a line). A zero-height `\hrule` plus kern before the title survives a page top, so the box stays clear of the header rule (`headsep` is 0, issue #106). There is no minipage: a task may break across pages (issue #113), but only between blocks (stem + part a), then each further part with the text before it, cut also at `\Seitenumbruch`). Each pass writes block heights to the .aux via `\pdfsavepos`; the next pass `\needspace`s a block that fits on a page, so moved blocks need one more pass. A line holding `\includegraphics` never ends a page. `Aufgabe` sets `\LARGE` before its spacing and `\hangindent`, because exams used to inherit it from `\Namenszeile` and the exercise preview (empty `\Namenszeile`) wrapped differently (issue #111). Decide placement only at block boundaries in vertical mode, never with `\pagetotal` mid-paragraph.
- Student-sheet solution fields (`\LoesungKaro`, `\LoesungLine`) are their own paragraph tied to the line above (`\LSG@field` in `Loesung.sty`), so a field never starts a page (issue #139); a trailing `\\` before them is dropped instead of leaving an empty line. Header cells reset `\arraystretch` and friends (`\SA@headreset`), because the output routine typesets the header inside whatever task the page broke in (issue #137).
- busytex local-compile quirks (`compiler.ts` / `compiler.worker.ts`; issue #51): The default engine is `server` where the admin allows `server_latex` (`DEFAULT_POLICY`, only an explicit choice is stored in the browser), else local. (1) A cold browser can throw spurious `File 'X.sty' not found` (e.g. `ulem.sty`) while `texlive-extra` downloads; the root layout therefore boots the engine early (`lib/latex/preload.ts` → worker message `preload`) once the workspace is `ok` and the effective engine is local. The loading dialog (`components/latex/LatexDownloadProgress.svelte`, store `lib/latex/downloadProgress.ts`) shows real compressed bytes while downloading, then the unpacking steps, and hides only when `runner.initialize()` is through. The bytes come from `scripts/fetch-interceptor.js` (nested busytex worker), which posts them as `Downloading data... (loaded/total)` with the manifest's compressed total; the worker keeps only messages with exactly that total (emscripten sends lines of the same shape with uncompressed totals). Changing that script changes the R2 mirror object name (`busytex-mirror.mjs`): re-run `mirror-busytex.yml` after merging. The bundled `latex-assets` come from the authenticated `GET /api/v1/latex-assets/*` (issue #87; `lib/latex/assets.ts` on the main thread, hash-checked against the manifest, handed to the worker via an `assets` message before `preload`/compile, since the worker cannot refresh a session). The endpoint answers `private, no-cache` + ETag; there is no static copy. (2) The `xetex_bibtex8_dvipdfmx` pipeline still runs xdvipdfmx after XeTeX failed, so the log ends in `Could not open ... main.xdv`; `describeCompileFailure` reports the XeTeX step's `!` errors instead. (3) texlyre-busytex's 180 s compile timeout rejects without stopping its worker, whose late answer would resolve the next compile: any thrown compile must `resetRunner()`. (4) Local WASM compiles can silently drop exercise content that compiles on the server, because the worker only reports failure when the engine reports `!success`. Root cause unknown; needs the browser console log of a local compile. (5) busytex's own rerun loop always runs XeTeX 4x (its `rerunfilecheck` pattern matches merely because hyperref loads that package; ~3.5 s per run), and the pipeline file is cached `immutable`, so it cannot be patched for existing users. `compiler.worker.ts` therefore runs single passes (`rerun: false`) and feeds `main.aux/.toc/.out` back until they stop changing (normally 2 runs; `Schulaufgabe.sty` hands each task's score to the next run through the aux file). The cached bundled-asset list is copied per compile; never push resources onto it. Previews show the Angabe as soon as it is ready (`onAngabe`), the Lösung follows.

## Gotchas

- **pdf.js loads only through `loadPdfjs()` (`lib/pdf/pdfjs.ts`), from its legacy build.** The modern build needs `Map#getOrInsertComputed`, which slightly older browsers lack, and then renders no scans at all; never import `pdfjs-dist` directly.
- **A swallowed API error still opens the global HTTP error modal.** `api.*` calls `httpErrorStore.showError()` before throwing. Pass `silentError: true` on anything with a local fallback, an offline-queue fallback, or an expected 409. Multi-step flows that report their own outcome (archive import/export) wrap their work in `collectHttpErrors()` (`stores/httpErrorStore.ts`) so stray errors land in their report instead.
- **Never re-encrypt a record that failed to decrypt.** `decryptX()` marks it (`decryptFailed: 'error' | 'locked'`, `lib/db/decryptGuard.ts`) and every `encryptX()` calls `assertEncryptable()` first, which throws. The old helpers returned a *blank* record on failure and the next save sealed the blanks over the real payload. `encryptX(rec, null)` throws for the same reason.
- **Every `db.exercises` (and other vault table) write takes `encryptX()` output.** A direct `put` of a decrypted record stores plaintext at rest (the old variant-creation path did). Prefer the repository `save()`. Use `db.exercises.put(await encryptExercise(rec, key))` only where the repository's `examExercises` junction merge is unwanted.
- **`sessionStore.unlock()` is async; always `await` it.** It writes the keys to sessionStorage before the store holds them, and `openWorkspace()` returns `unchecked` without a session key: an un-awaited unlock skipped the capabilities load, so every option (storage mode, server LaTeX) rendered disabled after a normal sign-in.
- **Admins never see teaching routes or call teaching endpoints** (issue #58; the server answers `403 ERR_TEACHER_ROLE_REQUIRED`). The root layout holds non-`isAdminPath()` routes until the role is known and redirects admins to `ADMIN_HOME`; shared layout or background code that calls teaching endpoints must skip admins (`openWorkspace()` state `admin`, never `ok`).
- **Routes must `await awaitSessionReady()` before touching the vault.** Svelte mounts children before the parent, so a route's `onMount` runs before `+layout.svelte` restores keys; without the gate the key is `null` on every F5.
- **Per-exercise scores go through `scoreRepository`**, never `db.exerciseScores` directly (the direct writes had no storage-mode branch, so `all-server` grading lived only in IndexedDB and was wiped on the idle timeout). The bulk write is a `PUT` keyed on `(submission_id, exercise_id)`, idempotent and safe to replay from the offline queue. There is deliberately **no plaintext `score` column**: the client seals score, `selectedOptions` and `omrMeta` into one payload.
- **Grading views must never clear an OMR-read MC score row.** The grade page's "score 0 + no strokes → ungraded" coercion and the manual grids' "empty input → `deleteOne`" used to delete rows carrying `omrMeta`, dropping the question from the MC verification queue. Outside the verify view, MC grading is optional: skip, or carry `selectedOptions`/`omrMeta` forward. The unsaved-changes prompt keys on `gradingStore.isDirty`, not on "strokes exist".
- **The grade page writes annotations only for the submission they were loaded for** (`gradingStore.strokesSubmissionId`, set by `ScanCanvasViewer` once a scan's annotations are applied, null while it loads). A save during a load leaves the annotation layer untouched; it used to write the previous student's strokes onto the shown one.
- **Shared exercises (issue #65) never enter the own library, Dexie or an exam.** The library's "Shared by others" view (`lib/api/exerciseSharing.ts`) is read-only and online-only; using one means copying it (`POST /exercises/{id}/copy`). `GET /exercises` returns own rows only, and archive import links only rows the account owns. Merges (resync, accepting a proposal) go through `exercise-library/MergeEditor.svelte`; proposals use `lib/api/exerciseContributions.ts`.
- **Map exercise API payloads only through `mapApiToExerciseRecord`** (`lib/repositories/exerciseRepository.ts`). Hand-rolled field lists dropped `variantKey`/`exerciseGroupId`/`isCurrent`, and the stripped record was `bulkPut` over the full one.
- **Import never writes before it has decrypted and resolved conflicts.** `decryptArchive()` touches nothing; `applyArchive()` writes under the **live** session key. Do not reintroduce a wipe before validation, and do not call `sessionStore.unlock()` with the archive key (the vault cannot re-derive it, so everything written afterwards dies with the tab).
- **`POST /auth/refresh` rotates the refresh token and treats a second use of a revoked one as theft**, revoking every session. `lib/api/client.ts` therefore funnels every refresh through `refreshSession()` (deduplicated per tab, serialized across tabs by a Web Lock, since tabs share the cookie) and, for `REFRESH_GRACE_MS` after a successful one, retries a 401 instead of refreshing again. Never call `/auth/refresh` directly; do not remove these guards.
- **Offline queue (`services/offlineQueue.ts`) takes only transient failures.** Repository write fallbacks call `enqueueOrThrow()`: network errors, 5xx, 408 and 429 are queued; any other 4xx shows the HTTP modal and is rethrown to the caller (a replay would be refused again). The flush runs on `online`, whenever the workspace opens (`ok`/`needs-choice`) and every minute while open; it removes only the entries it processed (`update()`), keeps 401/MFA failures, and drops refused ones with the root-layout banner (`rejectedWritesStore`).
- **`POST /exams` and `POST /exercises` are create-only** (a known id answers 409). Re-queuing that POST can never succeed; use `PATCH`. `saveExerciseEncrypted`/`saveExamEncrypted` already write to the server, so never follow them with a direct POST of the same record (a new exam with links goes through `examRepository.create`).
- **An absent `annotation_ciphertext_b64` means "don't touch", not "delete".** Deleting needs `clear_annotations: true`.
- **Example data** (issue #120): "Add example data" on the empty dashboard (`services/exampleData.ts`) imports `static/example-data/` (a plain archive payload + scan PDFs, generated by `docs/demo-instance/export-example.mjs`, never hand-edited) through `applyResolutions` (every exam/exercise/MC group as a copy, so accounts never share ids) and `applyArchive`. Regenerate it when the archive payload format changes.
- **Info posters** (issue #119): `/about` (public) shows `docs/posters/*.pdf`, imported with `?url` in `lib/about/posters.ts` (`server.fs.allow` in `vite.config.ts` lets `vite dev` serve them). Bundled, never fetched from GitHub.
- **Maintenance notices** (issue #130): `stores/maintenanceStore.ts` polls the public `GET /api/v1/maintenance` with a bare `fetch` (never the HTTP error modal; a failed poll keeps the last window, since the backend is down exactly then) and `layout/MaintenanceNotice.svelte` renders banners, the two reminders and the blocking notice. `api/client.ts` swallows `ERR_MAINTENANCE*` into that notice and refetches when a response's `Maintenance-Revision` header names a window the store does not know. Admins get banners only, so they can still end a window. Wording lives in `maintenance/text.ts`.
- **"What's new" after an update** (issue #94): `UpdateNotice.svelte` shows the release notes inlined from root `RELEASE_NOTES.md` (written with `VERSION` by `deploy-release.yml`, `__RELEASE_NOTES__` in `vite.config.ts`) once per version change, rendered by `utils/releaseNotes.ts` (token model, never HTML). Its reload prompt stays hidden while a maintenance window is in `warning`/`final`/`down` (issue #148). Never fetch notes from GitHub at runtime: `tests/cspHeaders.test.ts` forbids off-origin hosts in `src/`.
