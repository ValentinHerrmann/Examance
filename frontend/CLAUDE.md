# Frontend conventions

Loads when working under `frontend/`. Cross-cutting rules are in the root `CLAUDE.md`.

SvelteKit 3 on **Svelte 5 (runes only, no legacy syntax)**, TypeScript 6, Vite 8 (Rolldown), Tailwind v4, `adapter-static` → `build/`. Kit config lives in `vite.config.ts` (`sveltekit({ … })`; there is no `svelte.config.js`). Imports use `#lib/…` (`package.json` "imports" + a matching tsconfig `paths` entry); worker URLs stay relative (`lib/workers/spawn.ts`). Node is pinned in `.node-version` (Kit 3 needs ≥ 22.17). `dexie` is the encrypted IndexedDB cache (and, in hybrid mode, the home of results); `texlyre-busytex` is the browser LaTeX engine. `svelte-check --threshold error` stays clean. Build/CSP/BusyTeX details: `docs/dev/build_and_csp.md`.

## Components

- New components go in `src/lib/components/<feature>/`. Shared primitives live in `components/ui/` (list: `ui/index.ts`, import from `#lib/components/ui`). Loose files at the `components/` root are legacy; don't copy them.
- **Raw exports** (issue #82) live in `src/lib/export/` (plain ZIP via `ZipBuilder`, dialog `components/export/ExportOptionsModal`). Their `manifest.json` (`export/zipManifest.ts`) is read back by `archive/zipImport.ts`; a field added to it needs the importer too, and a breaking change bumps `ZIP_FORMAT_VERSION`. Burned-in graded PDFs come only from `renderGradedPdf` (`export/gradedPdf.ts`), strokes only from `grading/strokeRenderer.ts`, printed score boxes only from `grading/scoreBoxes.ts` and scan registration only from `grading/omrRegistration.ts` (issue #187); exam sources from `prepareExamSources`, exercise documents from `buildExerciseDocument`. Reuse them, don't fork.
- Routes hold data loading, handlers and session state; components hold markup. The two largest pages delegate whole flows to components (`exam/ExamMetadataEditDialog`, `exam/ExamExercisePicker`, `lib/exam/loadExam.ts`; the library's `exercise-library/*Flow.svelte`), each opened through an exported `open()`. Wire with callback props (`onAction={handler}`, `bind:value` on `$bindable` props); no `createEventDispatcher`, `on:` directives, `<slot>` or `export let`. Form primitives (`TextInput`, `Textarea`, `Select`, `Radio`, `SuggestInput`) take DOM-named handler props (`oninput`, `onchange`, …) and compose them with their own.
- Prop-drilling exception: `src/lib/grading/gradingStore.ts`. Leaf grading components subscribe directly (15+ interdependent fields, justified in-file).
- **One component per job (the reuse map; extend these, and add every new shared part here)**: every score save goes through `grading/scoreService.ts` (`saveSubmissionScores`, `createStudentWithSubmission`), both manual-grading directions are `manual-grading/ScoreGrid` (`orientation`), every export through `export/ExportOptionsModal` (readable ZIP and/or the password-protected backup with "without exercise texts"), confirms through `ui/ConfirmDialog` (`busy`, `error`, `confirmDisabled`), icon-badge dialogs through `ui/HeroDialog`, backup/recovery codes through `security/SetupCodesDialog`, every vault open through `openAcceptingChange` + `security/EnvelopeChangedDialog` (changed key copies, issue #180), factor cards through `security/FactorCard`, admin feature tables through `admin/FeatureMatrix`, the passkey and code steps of sign-in and reset through `services/secondFactor.ts`, dirty-form close confirms through `utils/dirtyClose.svelte.ts`, grading score rows (exercise and part) through `grading/ScoreRow`. The MC verification item is a view of `/exam/[id]/verify` (`verifyHref`); `/verify-item` only redirects.
- **Runes rules that protect storage behaviour** (the Svelte 4 → 5 migration relied on them):
  - Side effects are `$effect.pre` blocks that read their trigger names first and run the body in `untrack(…)`; otherwise a load/save re-fires whenever anything it reads changes. Keep existing guards (`loadSeq`, `loadedFor`, …).
  - A `$derived` over a store (`$derived($store.x)`) changes synchronously on `set`: compute a target index once, never re-read the derived after setting it (the grade page's Next loaded the student after next and saved their MC rows onto the wrong one, issue #85).
  - Put `$effect.pre` blocks **at the end of the instance script**: they run synchronously where declared, so one above a `let` it (or a function it calls) touches throws a TDZ error (Svelte 4 ran `$:` after all declarations).
  - Records and collections that reach repositories, Dexie, stores, workers or crypto are `$state.raw` and updated by reassignment (`arr = [...arr, x]`). A deep `$state` Proxy breaks `structuredClone`/IndexedDB/`postMessage` and identity checks. Deep `$state` is for primitives and local edit buffers only; pass those on as `$state.snapshot(x)`.
  - `onwheel`/`ontouch*` are passive in Svelte 5. A handler that calls `preventDefault()` needs a non-passive listener (see `ZoomableImage`, `grading/scanZoom.ts`).

## Design system (Artemis look, tokens re-implemented, no code copied)

- **Inline Tailwind utilities in markup** are the house dialect. A component `<style>` block is only for what utilities cannot express (a class shared by many siblings, a keyframe). Never add a `.css` file; the only ones are `src/app.css` and `routes/+layout.css`.
- **Light + dark** via `<html data-theme>`, resolved by `lib/stores/theme.ts` (pref `bg_theme`: `system`/`light`/`dark`). An inline no-flash script in `app.html` applies it before first paint; its storage key must stay in sync with the store.
- **Tokens** live in `@theme static` blocks in `src/app.css` (light plus a dark override set). Use the token utility (`bg-surface-raised`), never a raw hex or Tailwind shade; widths are `max-w-form|narrow|medium|wide|page`, z-index goes through `--z-dropdown`/`--z-modal`/`--z-toast`.
- **Rules**: never use a fill colour (`primary`, `danger`, …) as text colour; use `accent` / `*-fg`. Radius `md` for controls and panels, `xl` for cards and dialogs. No emoji/glyph chrome: icons are FontAwesome through `ui/Icon` with per-icon imports from `@fortawesome/free-solid-svg-icons`. Variant maps (`{ primary: "bg-primary …" }`) must hold literal class strings so Tailwind sees them. `PageShell` is the one page root.
- **Overview lists** (exam page, exercise library) share `ui/FilterLayout`, `ui/ExpandableCard`, `common/DeleteWithUsageModal` and `stores/previewFlow` + `common/PreviewHost`; extend them, don't fork (details: `docs/dev/ui_shell.md`). Every compiled-PDF preview offers "Report LaTeX layout problem" (`DualPdfPreview` footer, `layout-report/LayoutReportButton`).
- **Modal** (every dialog goes through it): sizes `small|medium|large|full` + `tall`; backdrop click is off by default (`closeOnBackdrop`) so a stray click cannot discard input; inside the panel use container variants (`@md:`/`@xl:`); scroll lock locks `.app-main` (`lib/utils/scrollLock.ts`); inline errors go through its `error` prop (`errorActions` for a retry).
- **Tables**: `.data-table` (+ `-compact|-striped|-hover`) in `app.css`, wrapped in `TableScroller`.

## Responsive and app shell

- **Mobile-first, always.** Unprefixed classes describe the phone; `sm:`/`md:`/`lg:`/`xl:` add back. Tailwind's default breakpoints only (640/768/1024/1280). **Never** `max-[900px]:`, `max-md:`, or a raw `@media` in component code. Every grid/flex child that can hold wide content needs `min-w-0`.
- `lib/stores/viewport.ts` (`minWidth(bp)`, `isDesktop`, `mediaQuery`) is only for places where a narrow screen changes *behaviour*. Anything purely visual belongs in a breakpoint variant.
- **Target devices**: unscaled 1920×1080 (primary); 1920×1080 laptops at 125/150 % scaling (1536×730, 1280×600, tight height); iPad Pro 12.9″ portrait 1024 (= `lg`) and landscape, touch/pencil; 6–7″ phones portrait. Touch targets ≥44px via `pointer-coarse:`.
- **Shell** (`routes/+layout.css`): `.app-layout` is `100dvh` with `overflow: clip`, body is `overflow: hidden`, and `.app-main` is the only scroller. `AppFooter` is the last child of `.app-main` on every route; the grade root fills via `flex-1 min-h-0`. Don't reintroduce `overflow: hidden` on the layout, don't nest a second `100vh`/`100dvh`, and never put `min-h-full`/`h-full` on a page root (page plus footer would overflow by the footer's height); centred pages use `PageShell center`. `overflow: hidden` still lets anchor jumps, `focus()` and `scrollIntoView` scroll the document (a gap under the footer); the root layout resets it, and in-page links scroll `.app-main` themselves (`settings/SectionNav`). `.app-main` is `position: relative` on purpose: an absolutely positioned `sr-only` deep in a tall page would otherwise be placed against the viewport and make the document scroll.
- Navbar, drawer, `PreviewBanner`, the exercise editor on small screens and cross-links (`ui/LinkButton` opens a dialog in place, `ui/CrossLink` opens a page in a new tab, hrefs from `lib/utils/links.ts`): `docs/dev/ui_shell.md`. Re-measure the header at 320px after adding a control, and keep the code editor in the first screen on 360×780 and 1280×600.
- E2E: `npm run test:e2e` (Playwright: `desktop`, `ipad-portrait`, `phone`; CI runs only `layout.spec.ts` and `a11y.spec.ts` on those three, issue #183). API calls go to the in-memory fake `tests/helpers/fakeApi.ts`, so no backend runs; helpers in `e2e/helpers/`. A request the fake cannot answer fails the test: extend the fake, not the app.

## i18n (German / English)

UI text lives in typed catalogs under `src/lib/i18n/`.

- `de/<ns>.ts` is the **source of truth** (`export const <ns> = {...} as const`). `en/<ns>.ts` is typed `Translations['<ns>']`, so a missing key is a `svelte-check` error. A new namespace goes into both `de/index.ts` and `en/index.ts`.
- Markup: `{$t("ns.key")}`, `{$t("ns.key", { name })}`. Plain `.ts`, `alert`/`confirm`/`prompt`: `translate("ns.key")`. Runtime-composed keys: `tOptional` / `translateOptional`. Dates and numbers: `$fmt.date` / `$fmt.number` / `$fmt.percent` from `lib/utils/format.ts`.
- Backend errors are localized **client-side** by the `code` the API sends next to its English `detail` (`errors.code.<CODE>`, applied in `lib/api/client.ts`); `err.message` stays the fallback.
- **Exam/PDF output is deliberately NOT translated**: `Schulaufgabe.sty` captions, `\begin{Aufgabe}`, `\Loesung*`, the MC rubric prose and German seed defaults (`testart`/`fach`/`title`) are exam content and a stable macro API. `routes/exam/new` keeps `toLocaleDateString("de-DE")` as the `datum` default because that value is printed in the PDF.
- Legal pages: German is legally binding (§ 18 MStV, § 5 DDG, Art. 12 DSGVO). `en/legal.ts` holds the German text as a placeholder; **never** machine-translate it. The operator's identity comes only from the `VITE_LEGAL_*` build variables (`lib/legal/operator.ts`, `docs/hosting.md` §5.1), never from committed text; retention numbers come from `GET /privacy/retention`.
- `tests/locale.test.ts` guards detection, persistence, interpolation and de/en key parity.

## Exams and MC (details: `docs/dev/mc_model.md`)

- Grading and statistics are strictly per question (`exerciseId`); `ExamMcGroup` is only LaTeX layout metadata.
- **Group membership lives on the junction row** (`examExercises.mcGroupId`/`subIndex`, Dexie key `[examId+exerciseId]`): a `put`/`bulkPut` that omits them silently dissolves the group. Merge onto the stored record.
- `PATCH /exams/{id}` replaces `mc_groups` and `exercise_links` wholesale; `buildExamLinkPayload()` in `exam/[id]/+page.svelte` is the single builder of both.
- The editor's MC question is LaTeX, never escaped; options and answer key are read from the LaTeX (`printedMcOptions`), the stored `correct_answers` is only a fallback.
- `routes/exam/new` only creates an empty exam (`ExamMetadataEditor` in `create` mode); selection, groups, order, preview, logo and packages live on the exam page. There is no second preamble builder.

## LaTeX (details: `docs/dev/latex.md`; read it before touching a `.sty` file, `compiler*.ts` or a document builder)

- Exam documents come from `lib/exam/examPreview.ts` (`prepareExamSources`), exercise documents from `buildExerciseDocument`; reuse them.
- Part exercises, fixed scores, AFB and competencies are `.sty` macros, read and written only through `lib/latex/exerciseStructure.ts` (no DB columns).
- Resource files: per exercise, flat sanitized names next to `main.tex`, staged under a throwaway id and committed on save (`exerciseResourceRepository.commit()` awaits `seedStaging`, or an early save deletes the files). SVG is refused (`lib/latex/resources.ts`, mirrored in `backend/app/services/latex_resources.py`).
- Builders mark exercise bodies (`markSource`); marked LaTeX never leaves the app or reaches a hash (`stripSourceMarkers`).
- User packages go only through `withPackages` (`lib/latex/packages.ts`, mirrored in `backend/app/services/latex_packages.py`); never add `\usepackage` lines to a builder.
- Server compiles are background jobs (`compileOnServer` polls `/compile/latex/jobs`); a thrown local compile must `resetRunner()`. Snippets and new packages must work in both engines (browser TeX Live 2026, Tectonic TeX Live 2022).

## Gotchas

- **pdf.js loads only through `loadPdfjs()` (`lib/pdf/pdfjs.ts`), from its legacy build.** Slightly older browsers render no scans with the modern build; never import `pdfjs-dist` directly. Its `getDocument` also supplies `wasmUrl` (decoders served at `/pdfjs/wasm/`); without it JBIG2/JPX scan layers render blank.
- **A swallowed API error still opens the global HTTP error modal.** `api.*` calls `httpErrorStore.showError()` before throwing. Pass `silentError: true` on anything with a local fallback, an offline-queue fallback, or an expected 409. Multi-step flows that report their own outcome (archive import/export) wrap their work in `collectHttpErrors()` (`stores/httpErrorStore.ts`) so stray errors land in their report instead.
- **Repository list reads throw on a failed server read** (`getAll`/`getByExamId` of submissions, students, exercises, exams; `submissionRepository.getById` answers `null` only for a 404). Hybrid reads from Dexie; only `examRepository.getAll` falls back to its local copy there. Never turn the error into `[]`/`null`: display callers show the page's error state ("no data" is a lie), integrity callers (archive, export, erasure, mover, conflicts) let it propagate.
- **Pseudonyms only through `crypto/pseudonymKey.ts` (issue #177).** Fresh input (a QR code, a minted id) gets `keyFromRaw(examId, raw)` or `pseudonymFor()` (`services/pseudonymRekey.ts`, which picks the exam's write version); stored rows are compared only by `joinKey(row)`. Never hash or re-key a stored `pseudonymHmac`: a version-2 value keyed again matches nothing, and an erasure then deletes nothing while reporting success. The raw value lives only in the sealed payload (`pseudonymRaw`), never in a plain column.
- **Every ciphertext goes through a codec with AAD (issue #178).** Records use `encryptX`/`decryptX`; scans and annotation layers use `sealScan`/`openScan`/`sealAnnotation`/`openAnnotation` (`db/dbEncryption.ts`), bound to the submission id, so mint the id before sealing. No bare `encrypt`/`decrypt` of record data.
- **Never re-encrypt a record that failed to decrypt.** `decryptX()` marks it (`decryptFailed: 'error' | 'locked'`, `lib/db/decryptGuard.ts`) and every `encryptX()` calls `assertEncryptable()` first, which throws. Re-encrypting a blank record seals the blanks over the real payload.
- **Every `db.exercises` (and other vault table) write takes `encryptX()` output.** A direct `put` of a decrypted record stores plaintext at rest. Prefer the repository `save()`. Use `db.exercises.put(await encryptExercise(rec, key))` only where the repository's `examExercises` junction merge is unwanted.
- **`sessionStore.unlock()` is async; always `await` it.** It writes the keys to sessionStorage, sealed under the tab's non-extractable wrapping key (`crypto/sessionWrap.ts`; never store a raw key there), before the store holds them, and `openWorkspace()` returns `unchecked` without a session key, so an un-awaited unlock renders every option disabled.
- **Admins never see teaching routes or call teaching endpoints** (issue #58; the server answers `403 ERR_TEACHER_ROLE_REQUIRED`). The root layout holds non-`isAdminPath()` routes until the role is known and redirects admins to `ADMIN_HOME`; shared layout or background code that calls teaching endpoints must skip admins (`openWorkspace()` state `admin`, never `ok`).
- **Routes must `await awaitSessionReady()` before touching the vault.** Svelte mounts children before the parent, so a route's `onMount` runs before `+layout.svelte` restores keys; without the gate the key is `null` on every F5.
- **Per-exercise scores go through `scoreRepository`**, never `db.exerciseScores` directly (a direct write ignores the storage mode). The bulk write is a `PUT` keyed on `(submission_id, exercise_id)`, idempotent and safe to replay from the offline queue. There is deliberately **no plaintext `score` column**: the client seals score, `selectedOptions` and `omrMeta` into one payload.
- **Grading views must never clear an OMR-read MC score row.** Deleting a row with `omrMeta` drops the question from the MC verification queue. Outside the verify view, MC grading is optional: skip, or carry `selectedOptions`/`omrMeta` forward. The unsaved-changes prompt keys on `gradingStore.isDirty`, not on "strokes exist".
- **The grade page writes annotations only for the submission they were loaded for** (`gradingStore.strokesSubmissionId`, set by `ScanCanvasViewer` once a scan's annotations are applied, null while it loads). A save during a load leaves the annotation layer untouched.
- **Shared exercises (issue #65) never enter the own library, Dexie or an exam.** The library's "Shared by others" view (`lib/api/exerciseSharing.ts`) is read-only and online-only; using one means copying it (`POST /exercises/{id}/copy`). `GET /exercises` returns own rows only, and archive import links only rows the account owns. Merges (resync, accepting a proposal) go through `exercise-library/MergeEditor.svelte`; proposals use `lib/api/exerciseContributions.ts`.
- **Map exercise API payloads only through `mapApiToExerciseRecord`** (`lib/repositories/exerciseRepository.ts`). Hand-rolled field lists drop fields, and the stripped record overwrites the full one.
- **Import never writes before it has decrypted and resolved conflicts.** `decryptArchive()` touches nothing; `applyArchive()` writes under the **live** session key. Do not reintroduce a wipe before validation, and do not call `sessionStore.unlock()` with the archive key (the vault cannot re-derive it, so everything written afterwards dies with the tab).
- **`POST /auth/refresh` rotates the refresh token and treats a second use of a revoked one as theft**, revoking every session. `lib/api/client.ts` therefore funnels every refresh through `refreshSession()` (deduplicated per tab, serialized across tabs by a Web Lock, since tabs share the cookie) and, for `REFRESH_GRACE_MS` after a successful one, retries a 401 instead of refreshing again. Never call `/auth/refresh` directly; do not remove these guards.
- **Offline queue (`services/offlineQueue.ts`, persisted in `db.offlineQueue`, flushes serialized across tabs by a Web Lock) takes only transient failures.** Repository write fallbacks call `enqueueOrThrow()`: network errors, 5xx, 408 and 429 are queued; any other 4xx shows the HTTP modal and is rethrown to the caller (a replay would be refused again). A flush removes only the entries it processed (`update()`), keeps 401/MFA failures and reports refused ones (`rejectedWritesStore`).
- **`POST /exams` and `POST /exercises` are create-only** (a known id answers 409). Re-queuing that POST can never succeed; use `PATCH`. `saveExerciseEncrypted`/`saveExamEncrypted` already write to the server, so never follow them with a direct POST of the same record (a new exam with links goes through `examRepository.create`).
- **An absent `annotation_ciphertext_b64` means "don't touch", not "delete".** Deleting needs `clear_annotations: true`.
- **Small features** (example data in `static/example-data/`: generated by `docs/demo-instance/export-example.mjs`, never hand-edited; info posters; maintenance notices; the "What's new" notice): rules in `docs/dev/ui_shell.md`. Never fetch release notes or posters from GitHub at runtime (`tests/cspHeaders.test.ts`).
