# LaTeX in the frontend: exercise structure, resources, compile errors, engines

Read on demand; moved out of `frontend/CLAUDE.md` so it does not load into every session. The never-rules stay there.

## Exercise structure (issues #77-#79)

Part exercises (`\begin{Teilaufgabe}[fixed]{subtitle}`, a/b/c with own score box), fixed scores (`\FestePunkte{N}` or the `[N]` option), requirement level (`\AFB{I|II|III}`) and competencies (`\Kompetenz{…}`) are LaTeX macros in `Schulaufgabe.sty`; there are no DB columns, so they travel with variants, copies, sharing and archives. The editor reads and writes them only through `lib/latex/exerciseStructure.ts` (`parseExerciseScore` delegates to it; its counting must match the `.sty`). Grading stays per exercise. MC bodies are rebuilt from question + options, so the editor strips and re-applies the AFB/competency tags around `buildMcOptionsLatex`. The editor's controls for them are `ExerciseStructurePanel`, shown in `ExerciseStructureModal` from the score button in the LaTeX header row (not inline, to keep the code editor in the first screen).

## LaTeX resource files and compiling

Teacher-uploaded files an exercise's LaTeX references (`\includegraphics{figure.png}`, `\input{data.tex}`). Any type except SVG (refused with a convert-to-PDF hint: `src/lib/latex/resources.ts`, mirrored in `backend/app/services/latex_resources.py`; keep the two in sync).

- Attached **per exercise**, referenced by **flat sanitized filename**; files are written next to `main.tex` in both engines, never in a subdirectory. Names that collide with a bundled `latex-assets` file (including the worker's flattened `sty/x.sty` → `x.sty`) are rejected at upload.
- Limits: 5 MB per file, 25 MB per exercise, 20 MB / 30 files per compile request; `BODY_LIMIT_COMPILE` 28 MB, `BODY_LIMIT_RESOURCE` 7 MB.
- Storage: Dexie `exerciseResources`, bytes AES-256-GCM encrypted; server table `exercise_resources`, bytes **plaintext** (same as `exercises.latex_body`; Tectonic cannot read ciphertext).
- The editor stages files under a throwaway id (never the exercise id) and `exerciseResourceRepository.commit()` moves the staged set onto the exercise on save. Cancel discards. The staged set is authoritative on commit: files removed while editing are deleted server-side too. The staging area is seeded asynchronously (`seedStaging`): the panel loads only once `seeded` is true and `commit` awaits the seed, otherwise the list opens empty and an early save would delete the files.
- Local compile: `compiler.ts` → worker `additionalFiles`. Server compile sends `resource_exercise_ids` for saved exercises and inline base64 only for staged/local-only files.
- Two exercises with *different* files under the same name is a hard error before compiling (`mergeResources`); identical bytes are deduped.
- `.bgproj` archives collect resource files per exported exercise through the repository (`listForExport` + `getBytes`), never by dumping Dexie, and the importer uploads them to the server only (issue #145; `docs/dev/storage_modes.md`).
- Resource API calls pass `silentError` and report in the panel; a 404 for an exercise the server has never seen must not raise the global toast.
- **Exam logo** (issue #46) is not a resource: the account choice (default MTG logo when unset, `none`, or own file) / per-exam override live on the server (`lib/latex/logo.ts`, `backend/app/services/logo.py`). The compile writes it as `examance-logo.<ext>` (reserved names) and `Schulaufgabe.sty`'s `\ExamLogo` prints whichever exists. Exam compiles pass `logo: await resolveCompileLogo(examId | null, useLocal)`; its fingerprint is part of the compile-cache hash. The logo is part of the exam everywhere it travels: `.bgproj` archives carry `examLogos` (export `exportExamLogo`, import `restoreExamLogo`, conflicts remap it with its exam) and the account export includes the files.
- **Compile errors** (issue #166) are `LatexCompileError` (`lib/latex/compileError.ts`) with the engine's full log (worker `log`, server 422 body `log`). Builders wrap user bodies in marker comment lines (`markSource`, `lib/latex/sourceMap.ts`, opt-in via `formatExerciseLatex`'s `sourceLabel`); `compileLatex` strips them and maps `l.<n>` back to exercise + editor line. Marked LaTeX must never leave the app or reach a hash: strip it (`stripSourceMarkers`) in exports, layout reports and the OMR template hash. Error sites render `components/latex/CompileErrorHelp` (`compileFailure(err)`: log, unmarked source, exercise ranges, engine): the likely cause, the AI-chat prompt dialog and the log button (issue #168, `lib/latex/errorHelp.ts`). The exercise editor's "Create AI prompt" (`exercise/ExercisePromptDialog`, `lib/latex/exercisePrompt.ts`) builds a writing prompt from the teacher's request; both prompts share `lib/latex/llmContext.ts` (English, for a model without context; `TEMPLATE_COMMANDS` mirrors the .sty files) and are the base for a later BYOK integration. Their previews use `latex/PromptPreview` (read-only CodeMirror with Markdown plus the editor's `latexLanguage`), never rendered HTML, since prompts hold exercise code and logs. Clipboard only; exercise code only on the user's tick; header fields (incl. `\ExamNotes`) are never included, also not via the log (`redactHeaderFields`).
- A missing graphic does not fail XeLaTeX. The worker reports `missingGraphics` and callers surface it; a successful compile is not proof the figures rendered.
- **LaTeX packages** (issue #108, rules in `docs/dev/latex_packages.md`): account list (`/user/latex-packages`, settings card), exam additions (`ExamRecord.latexPackages`, exam data dialog) and exercise `\usepackage` lines (editor panel, kept in the LaTeX so they travel) are merged by `lib/latex/packages.ts`, mirrored in `backend/app/services/latex_packages.py` (keep the logic in sync; the rule tables are one shared file, `backend/app/services/latex_package_rules.json`). Every document builder writes the result before `\documentclass` with `withPackages` (options only via `\PassOptionsToPackage`, packages in `\ExamancePackages`, which `packages.sty` runs before hyperref); never add `\usepackage` lines to a builder for user packages. Common TikZ libraries are preloaded in `packages.sty` (issue #107).
- The task score box sits at the right end of the title line (bottom on the baseline, `\hangindent` shortens that line), like the `Teilaufgabe` box. Never a `wrapfigure` (it left `\linewidth` 3cm short for the whole first paragraph, so grids came out narrow, and wrapped differently per document; issues #140, #138) and no band above the title (wasted a line). A zero-height `\hrule` plus kern before the title survives a page top, so the box stays clear of the header rule (`headsep` is 0, issue #106). There is no minipage: a task may break across pages (issue #113), but only between blocks (stem + part a), then each further part with the text before it, cut also at `\Seitenumbruch`). Each pass writes block heights to the .aux via `\pdfsavepos`; the next pass `\needspace`s a block that fits on a page, so moved blocks need one more pass. A line holding `\includegraphics` never ends a page. `Aufgabe` sets `\LARGE` before its spacing and `\hangindent`, because exams used to inherit it from `\Namenszeile` and the exercise preview (empty `\Namenszeile`) wrapped differently (issue #111). Decide placement only at block boundaries in vertical mode, never with `\pagetotal` mid-paragraph.
- Student-sheet solution fields (`\LoesungKaro`, `\LoesungLine`) are their own paragraph tied to the line above (`\LSG@field` in `Loesung.sty`), so a field never starts a page (issue #139); a trailing `\\` before them is dropped instead of leaving an empty line. Code solutions use the `LoesungCode` environment (issue #163), the only solution macro that may hold `lstlisting`; its student version typesets into the discarded box (not `comment`), so a `(*@\BE@*)` inside the listing still counts. Header cells reset `\arraystretch` and friends (`\SA@headreset`), because the output routine typesets the header inside whatever task the page broke in (issue #137).
- busytex local-compile quirks (`compiler.ts` / `compiler.worker.ts`; issue #51): The default engine is `server` where the admin allows `server_latex` (`DEFAULT_POLICY`, only an explicit choice is stored in the browser), else local. (1) A cold browser can throw spurious `File 'X.sty' not found` (e.g. `ulem.sty`) while `texlive-extra` downloads; the root layout therefore boots the engine early (`lib/latex/preload.ts` → worker message `preload`) once the workspace is `ok` and the effective engine is local. The loading dialog (`components/latex/LatexDownloadProgress.svelte`, store `lib/latex/downloadProgress.ts`) shows real compressed bytes while downloading, then the unpacking steps, and hides only when `runner.initialize()` is through. The bytes come from `scripts/fetch-interceptor.js` (nested busytex worker), which posts them as `Downloading data... (loaded/total)` with the manifest's compressed total; the worker keeps only messages with exactly that total (emscripten sends lines of the same shape with uncompressed totals). Changing that script changes the R2 mirror object name (`busytex-mirror.mjs`): re-run `mirror-busytex.yml` after merging. The bundled `latex-assets` come from the authenticated `GET /api/v1/latex-assets/*` (issue #87; `lib/latex/assets.ts` on the main thread, hash-checked against the manifest, handed to the worker via an `assets` message before `preload`/compile, since the worker cannot refresh a session). The endpoint answers `private, no-cache` + ETag; there is no static copy. (2) The `xetex_bibtex8_dvipdfmx` pipeline still runs xdvipdfmx after XeTeX failed, so the log ends in `Could not open ... main.xdv`; `describeCompileFailure` reports the XeTeX step's `!` errors instead. (3) texlyre-busytex's 180 s compile timeout rejects without stopping its worker, whose late answer would resolve the next compile: any thrown compile must `resetRunner()`. (4) Local WASM compiles can silently drop exercise content that compiles on the server, because the worker only reports failure when the engine reports `!success`. Root cause unknown; needs the browser console log of a local compile. (5) busytex's own rerun loop always runs XeTeX 4x (its `rerunfilecheck` pattern matches merely because hyperref loads that package; ~3.5 s per run), and the pipeline file is cached `immutable`, so it cannot be patched for existing users. `compiler.worker.ts` therefore runs single passes (`rerun: false`) and feeds `main.aux/.toc/.out` back until they stop changing (normally 2 runs; `Schulaufgabe.sty` hands each task's score to the next run through the aux file). The cached bundled-asset list is copied per compile; never push resources onto it. Previews show the Angabe as soon as it is ready (`onAngabe`), the Lösung follows.

## LaTeX palette

- **LaTeX palette**: general chips in `lib/latex/quickInsertMacros.ts` (labels `editor.macros.*`), subject tabs in `lib/latex/subjectSnippets.ts` (labels in the `snippets` namespace, MINT topics from LehrplanPLUS Gymnasium). The palette header links to the public snippet demo (`SNIPPET_DEMO_URL`, `lib/utils/links.ts`). Every package a snippet uses is preloaded by `packages.sty` (chemfig, circuitikz, mhchem since issue #154); a snippet never adds `\usepackage` lines. Check new snippets against both engines: the browser bundle (TeX Live 2026) lacks some packages (mhchem, chemgreek, simplekv, bbding, pifont, struktex are vendored in `backend/latex-assets/sty/` for it; the worker flattens `sty/*.sty` and `sty/*.tex`), Tectonic's bundle is TeX Live 2022 (chemfig 1.5+: `\charge`, no `\lewis`).
