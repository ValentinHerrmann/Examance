# LaTeX in the frontend: exercise structure, resources, compile errors, engines

The short rules that must never be broken in this area are in `frontend/CLAUDE.md`.

## Exercise structure (issues #77-#79)

Part exercises (`\begin{Teilaufgabe}[fixed]{subtitle}`, a/b/c with own score box), fixed scores (`\FestePunkte{N}` or the `[N]` option), requirement level (`\AFB{I|II|III}`) and competencies (`\Kompetenz{…}`) are LaTeX macros in `Schulaufgabe.sty`; there are no DB columns, so they travel with variants, copies, sharing and archives. The editor reads and writes them only through `lib/latex/exerciseStructure.ts` (`parseExerciseScore` delegates to it; its counting must match the `.sty`). Grading is per exercise, optionally per part: part scores live in the sealed score payload (`partScores`, `grading/partScores.ts`, issue #187). MC bodies are rebuilt from question + options, so the editor strips and re-applies the AFB/competency tags around `buildMcOptionsLatex`. The editor's controls for them are `ExerciseStructurePanel`, shown in `ExerciseStructureModal` from the score button in the LaTeX header row (not inline, to keep the code editor in the first screen).

## LaTeX resource files and compiling

Teacher-uploaded files an exercise's LaTeX references (`\includegraphics{figure.png}`, `\input{data.tex}`). Any type except SVG (refused with a convert-to-PDF hint: `src/lib/latex/resources.ts`, mirrored in `backend/app/services/latex_resources.py`; keep the two in sync).

- Attached **per exercise**, referenced by **flat sanitized filename**; files are written next to `main.tex` in both engines, never in a subdirectory. Names that collide with a bundled `latex-assets` file (including the worker's flattened `sty/x.sty` → `x.sty`) are rejected at upload.
- Limits: 5 MB per file, 25 MB per exercise, 20 MB / 30 files per compile request; `BODY_LIMIT_COMPILE` 28 MB, `BODY_LIMIT_RESOURCE` 7 MB.
- Storage: Dexie `exerciseResources`, bytes AES-256-GCM encrypted; server table `exercise_resources`, bytes **plaintext** (same as `exercises.latex_body`; the server engine cannot read ciphertext).
- The editor stages files under a throwaway id (never the exercise id) and `exerciseResourceRepository.commit()` moves the staged set onto the exercise on save. Cancel discards. The staged set is authoritative on commit: files removed while editing are deleted server-side too. The staging area is seeded asynchronously (`seedStaging`): the panel loads only once `seeded` is true and `commit` awaits the seed, otherwise the list opens empty and an early save would delete the files.
- Local compile: `compiler.ts` → worker `additionalFiles`. Server compile sends `resource_exercise_ids` for saved exercises and inline base64 only for staged/local-only files.
- Two exercises with *different* files under the same name is a hard error before compiling (`mergeResources`); identical bytes are deduped.
- `.bgproj` archives collect resource files per exported exercise through the repository (`listForExport` + `getBytes`), never by dumping Dexie, and the importer uploads them to the server only (issue #145; `docs/dev/storage_modes.md`).
- Resource API calls pass `silentError` and report in the panel; a 404 for an exercise the server has never seen must not raise the global toast.
- **Exam logo** (issue #46) is not a resource: the account choice (default MTG logo when unset, `none`, or own file) / per-exam override live on the server (`lib/latex/logo.ts`, `backend/app/services/logo.py`). The compile writes it as `examance-logo.<ext>` (reserved names) and `Schulaufgabe.sty`'s `\ExamLogo` prints whichever exists. Exam compiles pass `logo: await resolveCompileLogo(examId | null, useLocal)`; its fingerprint is part of the compile-cache hash. The logo is part of the exam everywhere it travels: `.bgproj` archives carry `examLogos` (export `exportExamLogo`, import `restoreExamLogo`, conflicts remap it with its exam) and the account export includes the files.
- **Compile errors** (issue #166) are `LatexCompileError` (`lib/latex/compileError.ts`) with the engine's full log (worker `log`, server 422 body `log`). Builders wrap user bodies in marker comment lines (`markSource`, `lib/latex/sourceMap.ts`, opt-in via `formatExerciseLatex`'s `sourceLabel`); `compileLatex` strips them and maps `l.<n>` back to exercise + editor line. Marked LaTeX must never leave the app or reach a hash: strip it (`stripSourceMarkers`) in exports, layout reports and the OMR template hash. Error sites render `components/latex/CompileErrorHelp` (`compileFailure(err)`: log, unmarked source, exercise ranges, engine): the likely cause, the AI-chat prompt dialog and the log button (issue #168, `lib/latex/errorHelp.ts`). The exercise editor's "Create AI prompt" (`exercise/ExercisePromptDialog`, `lib/latex/exercisePrompt.ts`) builds a writing prompt from the teacher's request; both prompts share `lib/latex/llmContext.ts` (English, for a model without context; `TEMPLATE_COMMANDS` mirrors the .sty files) and are the base for a later BYOK integration. Their previews use `latex/PromptPreview` (read-only CodeMirror with Markdown plus the editor's `latexLanguage`), never rendered HTML, since prompts hold exercise code and logs. Clipboard only; exercise code only on the user's tick; header fields (incl. `\ExamNotes`) are never included, also not via the log (`redactHeaderFields`).
- A missing graphic does not fail XeLaTeX. The worker reports `missingGraphics` and callers surface it; a successful compile is not proof the figures rendered.
- **LaTeX packages** (issue #108, rules in `docs/dev/latex_packages.md`): account list (`/user/latex-packages`, settings card) and exercise `\usepackage` lines (editor panel, kept in the LaTeX so they travel) are merged by `lib/latex/packages.ts`, mirrored in `backend/app/services/latex_packages.py` (keep the logic in sync; the rule tables are one shared file, `backend/app/services/latex_package_rules.json`). Every document builder writes the result before `\documentclass` with `withPackages` (options only via `\PassOptionsToPackage`, packages in `\ExamancePackages`, which `packages.sty` runs before hyperref); never add `\usepackage` lines to a builder for user packages. Common TikZ libraries are preloaded in `packages.sty` (issue #107).
- The task score box sits at the right end of the title line (bottom on the baseline, `\hangindent` shortens that line), like the `Teilaufgabe` box. Never a `wrapfigure` (it left `\linewidth` 3cm short for the whole first paragraph, so grids came out narrow, and wrapped differently per document; issues #140, #138) and no band above the title (wasted a line). A zero-height `\hrule` plus kern before the title survives a page top, so the box stays clear of the header rule (`headsep` is 0, issue #106). There is no minipage: a task may break across pages (issue #113), but only between blocks (stem + part a), then each further part with the text before it, cut also at `\Seitenumbruch`). Each pass writes block heights to the .aux via `\pdfsavepos`; the next pass `\needspace`s a block that fits on a page, so moved blocks need one more pass. A line holding `\includegraphics` never ends a page. `Aufgabe` sets `\LARGE` before its spacing and `\hangindent`, because exams used to inherit it from `\Namenszeile` and the exercise preview (empty `\Namenszeile`) wrapped differently (issue #111). Decide placement only at block boundaries in vertical mode, never with `\pagetotal` mid-paragraph.
- Score boxes carry invisible `omr://__box__` links (`\OmrScoreSlot`, `\OmrScoreCell` in `Loesung.sty`, issue #187) so grading can fill them in (`docs/dev/omr.md`). The link wraps the existing blank and adds no width: a changed box width would move line and page breaks of every printed exam.
- `\punktraster[size]{rows}` and `\LoesungPunktraster{solution}{rows}` always draw a dot grid; the exam option `karopunkte` (exam switch `dottedFields`) makes `\kariert` and `\LoesungKaro` draw dots too (issue #314).
- Student-sheet solution fields (`\LoesungKaro`, `\LoesungLine`) are their own paragraph tied to the line above (`\LSG@field` in `Loesung.sty`), so a field never starts a page (issue #139); a trailing `\\` before them is dropped instead of leaving an empty line. Code solutions use the `LoesungCode` environment (issue #163), the only solution macro that may hold `lstlisting`; its student version typesets into the discarded box (not `comment`), so a `(*@\BE@*)` inside the listing still counts. Header cells reset `\arraystretch` and friends (`\SA@headreset`), because the output routine typesets the header inside whatever task the page broke in (issue #137).
- **The browser engine** (issue #346; `compiler.ts`, `compiler.worker.ts`, `lib/latex/engine/`; design and measurements in `docs/dev/latex_performance.md`):
  - **Which engine.** The default is `server` where the admin allows `server_latex` (`DEFAULT_POLICY`; only an explicit choice is stored in the browser), else local.
  - **What it runs.** Our own asyncified XeTeX and xdvipdfmx WASM, committed gzipped in `frontend/static/core/latex-engine/`. XeTeX carries the source-provenance patch (below, "Click-to-source and inline editing"). They are built by `frontend/scripts/latex-engine/build-engine.sh` (pinned TeX Live source and emsdk), and CI rebuilds them and compares the checksums (`.github/workflows/latex-engine.yml`). Never hand-edit or recompress those files.
  - **The TeX tree is the server's.** It comes from `GET /api/v1/texlive/*` (`backend/app/services/texlive_tree.py`, the image's `/opt/texlive`, plus the runner's `texmf.cnf`), so both engines read identical files.
    - The worker asks the main thread for files (`tree-request`), because only the main thread can refresh a session.
    - Files are fetched on first read (an Asyncify unwind at `fd_read`) and kept in IndexedDB (`examance-texlive`, cleared when the tree version changes).
    - The template's files (`engine/templateFiles.json`) are prefetched at boot. Re-record that list with `node-run.mts` (`RECORD_TREE`) when the template starts loading other packages.
  - **Boot.** The root layout boots the engine early (`lib/latex/preload.ts`, worker message `preload`) once the workspace is `ok` and the effective engine is local. The loading dialog (`components/latex/LatexDownloadProgress.svelte`, store `lib/latex/downloadProgress.ts`) counts the engine files plus the template prefetch.
  - **Sessions.** `compileWithCache` passes exercise and exam slots as `session`. The worker keeps at most two engine sessions (one on devices with 4 GB or less); an edit resumes from the checkpoint before the first input it changed, and other documents compile from scratch.
    - Above the memory budget a session runs without checkpoints.
    - An engine that cannot even be instantiated answers `unavailable`, and `compiler.ts` then compiles on the server without asking, where the account may use it.
    - A thrown compile drops its session (the old "resetRunner" rule).
  - **Formats.** A format per preamble is dumped in the browser exactly like the server's (`engine/format.ts` mirrors `split_preamble`, the dump wrapper and the flags of `services/texrunner.py`: change both together) and kept in IndexedDB (`examance-latex-formats`, eight formats).
  - **Assets.** The bundled `latex-assets` come from the authenticated `GET /api/v1/latex-assets/*` (issue #87; `lib/latex/assets.ts` on the main thread, hash-checked against the manifest, handed to the worker via an `assets` message before `preload` or compile). The endpoint answers `private, no-cache` with an ETag, and there is no static copy. The worker exposes `sty/*.sty` and `sty/*.tex` flat as well.
  - **Passes.** The worker runs passes until `main.aux`, `.toc` and `.out` settle (at most 4, like the server). Aux seeds count only for a fresh session, and a stale seed is retried once without. `Schulaufgabe.sty` hands each task's score to the next pass through the aux file.
  - **xdvipdfmx** gets every file the XeTeX session saw (`engine/pdfStep.ts`): it embeds the logo, the bundled images and the exercise figures that XeTeX only measured.
  - **Failures.** xdvipdfmx runs only after a successful XeTeX run; `describeCompileFailure` and `compileLogForUser` (`lib/latex/compileLog.ts`) still report the XeTeX step's `!` errors behind an xdvipdfmx fatal.
  - **Previews** show the Angabe as soon as it is ready (`onAngabe`), and the Lösung follows.
  - **Live preview** (exercise editor, browser engine only): at once on an edit of name, code or files (300 ms after the last one on devices with 4 GB or less, `LIVE_DELAY_MS`), once the session compiled or shows a PDF. `EditorPreview.compile` runs one compile at a time and then only the newest input, so a stale PDF never shows last; a failure keeps the last good PDF. `PdfEmbedViewer` mounts a new PDF hidden behind the shown one and swaps once a page in view has rendered, keeping zoom and scroll (`whenEmbedPdfShown`, `lib/pdf/embedpdf.ts`), so no loading screen flashes.
  - **Default and fallback.** The browser engine is the default (`DEFAULT_POLICY`). Every browser is moved to it once (`switchToLocalOnce`, key `bg_latex_local_switch`) by `settings/LocalLatexNotice`, which explains it in a one-time dialog after sign-in with a way back; new accounts (the tab saw `needs-choice`), admins and accounts without `server_latex` move without the dialog. Only an engine failure (`LocalEngineFailedError`: boot, download, worker crash, timeout; `LocalEngineUnavailableError` for no memory) goes to the server (`fallBackToServer`), never a LaTeX error, which would fail there too; the fallback sets `engineFallbackStore`, and the notice then offers once per tab to compile on the server from now on.
- **Click-to-source and inline editing** (issue #347):
  - **Provenance in the engine.** `frontend/scripts/latex-engine/provenance/` patches our XeTeX build (merged with `tie` by `build-engine.sh`, typesetting unchanged: the XDV stays byte-identical to stock):
    - every token remembers where it came from (`prov_cur`, a 32-bit array parallel to `mem` in `provenance.c`): line*4096+column (UTF-16) in main.tex, 0 elsewhere;
    - SyncTeX stamps that origin on every node instead of the plain file line, so every record of main.tex (tag 1) is packed, with column 4095 for template code run while main.tex was read; interword spaces show as glue or kern points with the exact column of the space, also inside macro arguments;
    - each native word shipped out writes a line to `main.prov` (`w page h v width size n x1 … xn`, sp, SyncTeX's frame): its exact glyph positions.
    - Cost on the 12-task exam (November 2026): +3 % per compile, +2.5 % per replayed edit, +20 MB engine memory, checkpoints +0.3 %; edit replays stay byte-identical. Measure changes with `node-run.mts`.
  - **SyncTeX.** The worker writes `-synctex=-1` and posts `main.synctex`, `main.prov` and `synctexColumns: true`; the server writes `-synctex=1` only for `return_synctex` and answers it gzipped as `synctex_b64`, without columns or glyphs. Both report `synctex_line_shift`: with a format, the wrapper (`BEFORE_DUMP`/`AFTER_DUMP`, `FORMAT_LINE_SHIFT` on both sides) adds lines before the document body. All of it is kept in memory only (`compileCache.ts`), never in the sealed `compiledPdfs` store, so a reload loses clicks until the next compile.
  - **Labels.** `markSource(body, name, exerciseId)` writes `<exerciseId>|<name>`; `extractSourceMap` splits it into `SourceRange.label` (the name every error message shows) and `exerciseId`, so two exercises of the same name stay apart. `CompileResult.sourceRanges` carries the ranges of every compile and cache hit.
  - **Click to source** (`lib/latex/clickToSource.ts`): with glyphs (`inlineEdit/glyphMap.ts`), the glyph under the click, its word, the interword space before it (or after it, for the first word of a printed line) and the word's printed view give the exact character; the cursor goes before the glyph, or after it on its right half; ligatures are resolved by `glyphStarts`. Without glyphs (server compiles, the Exam step after a reload), the clicked word and its neighbours come from pdf.js text content and are searched in the source paragraph's printed view (`lib/latex/printedText.ts`). Accuracy: `scripts/latex-engine/click-accuracy.mts` clicks every printed word of a compiled sample (pdfminer boxes, truth by aligning printed and source words); November 2026, running text: 408 of 410 on the exact clicked character with glyphs, 409 of 410 on the right word without.
  - **Inline editing.** `PdfEmbedViewer` `edit` (`components/latex/PageEditLayer.svelte`, passed per pane by `DualPdfPreview`): taps and clicks through the tap filter (`lib/pdf/tap.ts`: one primary pointer, under 6 px and 300 ms; a click counts 1 caret, 2 word, 3 line), mouse drags, a hidden textarea for typing (keys and text go to the code editor through `LatexEditor` `replaceSelection`/`runKey`/`setSelection`), and the caret and selection boxes (`PreviewSync` `marks`, from `caretFor`/`selectionFor`). Page geometry comes only from `embedPdfPageLocator` (`lib/pdf/embedpdf.ts`: the scroll plugin's layout plus the scroller's live scroll offset; its stored visibility metrics lag behind). The CodeMirror document stays the single source: autosave, undo and the live preview work as for typing in the code. Nothing is drawn as provisional text: the live preview compiles at once on every edit (`LIVE_DELAY_MS`), so the page follows within about a second. The exercise editor edits in the pages; the Exam step only opens the clicked exercise in the editor (`ExamPreviewPanel onSourceClick`, `initialCursor`).
  - **Tests.** `e2e/editorClick.spec.ts` (server mode, a synced fake compile) and `e2e/inlineEdit.spec.ts`, which runs the real engine with the TeX tree of a local install served by the fake API (`tests/helpers/fakeTexTree.ts`; `backend/latex-texlive/install.sh` into `/opt/texlive`) and skips without one.

## LaTeX palette

- **LaTeX palette**: general chips in `lib/latex/quickInsertMacros.ts` (labels `editor.macros.*`), subject tabs in `lib/latex/subjectSnippets.ts` (labels in the `snippets` namespace, MINT topics from LehrplanPLUS Gymnasium). The palette header links to the public snippet demo (`SNIPPET_DEMO_URL`, `lib/utils/links.ts`). Every package a snippet uses is preloaded by `packages.sty` (chemfig, circuitikz, mhchem since issue #154); a snippet never adds `\usepackage` lines. Both engines read the same pinned TeX Live 2026 (the browser through `/api/v1/texlive`), so a snippet that compiles in one compiles in the other; a package missing from both goes into `backend/latex-texlive/packages.txt`. mhchem, chemgreek, simplekv, bbding, pifont and struktex are also vendored in `backend/latex-assets/sty/` (the worker flattens `sty/*.sty` and `sty/*.tex`).
