# CI and dependency audit

**`ci.yml` installs unpinned deps.** `uv pip install -e ".[dev]"` and `npm ci` both resolve to the newest allowed versions, so a new mypy or a fresh advisory turns CI red without a code change.

The frontend `npm audit` gate is deliberately scoped to `--omit=dev`: the build toolchain (Vite / SvelteKit / Svelte) never ships to a browser, so a dev-server-only advisory must not block deploys. The full tree is still reported (non-blocking). `@sveltejs/kit` sits in `devDependencies` for that reason, as in the SvelteKit template.

The `--omit=dev` tree is still not only shipped code: `@embedpdf/snippet`'s packages declare non-optional `svelte >=5` / `react` / `vue` peers, so npm counts Svelte (and its `devalue`) as "prod" although only the preact build is bundled.

Their advisories hit the gate. Fix with a lockfile bump (`npm audit fix`), never `--force`.

The `e2e` job runs the Playwright layout and accessibility specs (`frontend/e2e/layout.spec.ts`, `a11y.spec.ts`) on the `desktop`, `ipad-portrait` and `phone` projects (issue #183), so they cannot rot again. It is a matrix with one job per device and check group (`routes`: the route loops of `layout.spec.ts`; `a11y`: `a11y.spec.ts`, desktop and phone only; `shell`: the rest of `layout.spec.ts`), so the eight jobs run side by side in about three minutes; inside a job Playwright keeps one worker, since parallel workers made Argon2 and the dev server flaky. A new spec file runs in CI only once a group's `args` names it; a new test in `layout.spec.ts` lands in `shell` unless it matches the `routes` grep. The job caches `frontend/node_modules` (keyed on the lockfile and Node version, `npm ci` only on a miss) and installs only Chromium's headless shell. The browser's API calls go to the in-memory fake (`frontend/tests/helpers/fakeApi.ts`), so no backend or database runs. It installs with `--ignore-scripts` (the only install script in the tree is macOS-only fsevents) and calls the locked binaries in `node_modules/.bin`, never an on-demand `npx` download (SonarCloud S6505/S8543). It needs `svelte-kit sync` before Playwright loads its config (the tsconfig extends the generated `$app/tsconfig`), and on failure it uploads the HTML report as the `playwright-report-<device>-<group>` artifact. The functional suite and the other device projects stay local for run time; run them with `npm run test:e2e`.

The `docs` job builds the VitePress site in `docs/` (its own `package.json`, separate from the app), installing with `--ignore-scripts`: the only install scripts in its tree are esbuild's binary check (the binary comes from its platform package) and macOS-only fsevents. VitePress fails on dead internal links; links that leave the site (sources, PDFs, Marp slides) are rewritten to GitHub by `docs/.vitepress/config.mts`. Its dev-server advisories are not audited: the site is static HTML. `vitepress-plugin-mermaid` only accepts mermaid 10 or 11, so `docs/package.json` keeps mermaid 11 and forces the patched katex (GHSA-238p-pmpm-9mq7) through `overrides`; drop the override once the plugin accepts mermaid 12.

## SonarCloud

SonarCloud runs as automatic analysis (no scanner step in the workflows); its settings live in the root `.sonarcloud.properties`. The quality gate allows at most 3 % duplication on new code. The i18n catalogs are excluded from copy-paste detection because `en/*.ts` mirrors `de/*.ts` key for key by design. Loops that await on purpose one step at a time (memory bounds, the single LaTeX worker, the compile rate limit) carry `// NOSONAR: <reason>` on the flagged line instead of being parallelised.
