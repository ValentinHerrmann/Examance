# Exercise sharing, copies and contributions (backend)

The short rules that must never be broken in this area are in `backend/CLAUDE.md`. Background: `docs/data_flow_and_security.md` §3 "Exercise sharing".

- What a copy, resync or proposal carries is `EXERCISE_CONTENT_FIELDS` (projected by `content_of`); every other `Exercise` column is identity, share state or provenance. A new column must be classified in `tests/test_exercise_sharing.py` or that test fails.
- Copy provenance (`copied_from_exercise_id`, `synced_fingerprint`, `exercise_groups.source_group_id`) has no FK on purpose. Resync only adds versions (`next_version`, shared with `create_new_version`); it never updates a row an exam may link. Resource writes must set `content_sha256` (the fingerprint covers file bytes). Content-equal copy and source are in sync: `plan_groups` advances the copy's sync point itself (`_mark_synced`, provenance only, own rows only), so an identically accepted proposal needs no update.
- Contributions (`services/exercise_contributions.py`, router `exercise_contributions.py`, registered **before** the exercises router): the owner's library changes only on an explicit accept of an immutable snapshot, and only via `next_version`/`new_variant_row`. Every decision claims through `_close` (one conditional `UPDATE … WHERE status='pending'`, which also clears the payload); a 0 rowcount means 409. Writers into a group lock it (`plan_group(..., lock=True)`, `with_for_update`). A copied group (`copied_at`, never cleared, and set on any group a copied row is moved into) is never shared as one's own.
- **Duplicating own work** (issue #121): `duplicate_own_group` copies the current row per variant into a new group *without* provenance (no resync link); a duplicate of a copied group keeps `copied_at`, so duplicating never launders a copy into shareable own work. `POST /exams/{id}/duplicate` re-links the same exercises and never copies results.
- Sharing errors are `HTTPException` subclasses raised from the services (`ContributionError`, `ResyncConflict`); routers don't wrap them. Audit through `audit.log(db, request, teacher, action, target)`. Never read-and-write another account's rows (e.g. hashes): compute in memory. New enum values or backfills go into a new migration; never edit a migration the preview stack already ran.
