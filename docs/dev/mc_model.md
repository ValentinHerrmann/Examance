# Multiple Choice (MC) and exam data model

The short rules that must never be broken in this area are in `frontend/CLAUDE.md`.

- **MC question**: an individual `Exercise` / `ExerciseRecord` (`question_type: mc|sc|tf`, `correct_answers` JSON / `options` & `correctAnswers` arrays, `penalty`). Variants use the standard `exercise_group_id` + `variant_key`.
- **MC group (`\McExercise{a}{b}{c}`)**: a per-exam layout container (`ExamMcGroup` / `ExamMcGroupRecord`, 1+ sub-items, no cap on count or size) linking members via `ExamExercise.mc_group_id` and `sub_index`. Rendered into one `\begin{Aufgabe}` by `formatMcGroupLatex()` (`lib/latex/scoreParser.ts`; the server builds no exam LaTeX since M6). An exercise belongs to at most one group (staging rules: `lib/exam/mcGroupStaging.ts`, used by the exam page's `exam/ExamExercisePicker`).
- **Grading and statistics are strictly per question (`exerciseId`)**; `ExamMcGroup` is only LaTeX layout metadata.
- **Group membership lives on the junction row**, not on the exercise: `ExamExercise.mc_group_id`/`sub_index` server-side, `examExercises.mcGroupId`/`subIndex` in Dexie. The Dexie primary key is `[examId+exerciseId]`, so **any `examExercises.put`/`bulkPut` that omits those two fields silently dissolves the group** (it renders empty and its members reappear as standalone exercises). Always merge onto the stored record or carry the fields through from the API response.
- Group ids are **client-chosen and stable**; `_persist_mc_groups` keeps them and answers 409 on collision. `exam_exercises.mc_group_id` is `ON DELETE SET NULL`: dissolving a group must never delete its members' exam links.
- **New exam** (M1): `routes/exam/new` only hosts `ExamMetadataEditor` in `create` mode; it creates an empty exam and opens `/exam/[id]?library=open`. All exercise selection, MC groups, order, preview, logo and packages live on the exam page (`ExamLibraryModal` has "New exercise"). There is no second preamble builder.
- `PATCH /exams/{id}` replaces `mc_groups` and `exercise_links` wholesale. An exercise may appear **once** in `exercise_links` (`(exam_id, exercise_id)` is the primary key). `buildExamLinkPayload()` in `exam/[id]/+page.svelte` is the single builder for both the Dexie records and that payload; don't hand-roll a second one.
- Past 26 members the sub-label switches from `a)` to `1)`: `mcSubLabel` (`lib/grading/mcGroupLabels.ts`) and `formatMcGroupLatex` must agree. An MC question's option column count lives only in its LaTeX body as `\LoesungMulti[N]` (`lib/latex/mcOptions.ts`). Options and answer key are read from the LaTeX too (`printedMcOptions`: one per `\multi`/`\Lmulti`, in OMR `optionIndex` order); the stored `correct_answers` is only a fallback, since LaTeX-only edits (new variant, resync) leave it stale.
- In MC mode the editor shows only `exercise/McOptionsEditor`; the composed LaTeX (a duplicate of question + options) opens on demand in its own dialog ("LaTeX code").
- The editor's MC question is **LaTeX, never escaped** (`buildMcOptionsLatex`; escaping it on every rebuild corrupted it). Option texts are plain input and escaped, but an option keeps its parsed `source` until its text is edited, and text after the `\LoesungMulti` block survives a rebuild. Saving reads the options from the LaTeX instead of rebuilding it. While the block is unclosed (`malformed`, e.g. mid-typing) the MC editor never rebuilds. `LatexEditor`'s `onChange` fires only for user edits, never for an outside `value` change.
- `examItems` (the exam page's item order) is view state, rebuilt on load from persisted `order_index` via `buildExamItems()`. Group members share their group's `order_index`.
- **Page breaks** (`exams.page_breaks`, `ExamRecord.pageBreaks`): ids of the exercises / MC groups that start on a new page, plaintext layout metadata. `buildExerciseInputs(..., pageBreaks)` emits `\newpage` (never before the first block); archive import remaps the ids (`lib/exam/pageBreaks.ts`). The OMR template's `exercisesHash` (`computeOmrTemplateHash`) covers the answer key plus the blank sheet's whole LaTeX, so exercise edits, reordering, breaks and header changes mark it stale (issue #135); scan and verify rebuild it, the exam page only warns.
- **Name line** (issue #127, `exams.name_line`, `ExamRecord.nameLine`): the `Schulaufgabe.sty` option `namenszeile`, added only by `withExamOptions` (`lib/exam/examPreview.ts`). It keeps the QR box (same size, scanning unchanged) and adds a name line beside it.
- **MC correction legend** (issue #192, `exams.mc_correction_hint`, `ExamRecord.mcCorrectionHint`): `\McKorrekturHinweis` (`Loesung.sty`), one line showing cross / fill to withdraw / cross left of a filled box to re-select (the `marked`/`undone`/`redone` states of `omrShape.ts`), in both PDFs. `buildExerciseInputs` emits it only when on, under each MC group's instruction and after the title of each exercise with answer boxes (`printedMcOptions`), so existing exams' LaTeX and template hash stay unchanged. It is plain TikZ: never `\OmrBox`/`\OmrLink` in it, or it becomes bubbles.
- **Extra notes** (issue #156, `exams.extra_notes`, `ExamRecord.extraNotes`: `{title, description, minHeightCm, maxHeightCm}` or null): an optional karo block closing the exam. `buildExamLatex` ends the body with `\ExamNotes{title}{description}{min}{max}` (`extraNotesLatex`) for both PDFs; `Schulaufgabe.sty` skips it under `antworten` (student sheet only) and fills the last page between min and max. The printed title is German exam content, not translated. The toggle (`ExtraNotesField.svelte`) sits at the bottom of `ExerciseList` and saves like a page break.
- OMR detection internals: `docs/dev/omr.md`. Training-data donation: `docs/dev/training_donation.md`.
